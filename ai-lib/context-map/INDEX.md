## Database Summary

**Tabele (Faza 1):**
- `profiles` - 1:1 z `auth.users`, kolumny: email, full_name, role (enum: posel/administrator/pracownik/asystent; administrator = uprawnienia Posła), is_active, **office_id** (FK → offices), **phone**, **avatar_url**, **is_public** (default true), **password_set** (default false), **has_privacy_pin** (default false; zmieniają tylko RPC PIN-u), **scope_contacts/scope_cases/scope_events/scope_interpellations** (enum data_scope: own|all, default 'all'). SELECT: własny wiersz albo aktywny user + aal2
- `profile_secrets` - user_id, privacy_pin_hash (bcrypt), pin_failed_attempts, pin_locked_until. RLS bez polityk, brak grantów dla klienta - tylko RPC
- `offices` - biura poselskie: name, city, address, phone, email, is_main (jedno aktywne, partial unique index), is_active
- `audit_log` - id, user_id, user_email, action, entity_type, entity_id, metadata jsonb
- `mcp_tokens` - long-lived API tokeny dla MCP integracji: id, user_id, name, **token_hash** (sha256 hex unique), token_prefix, scopes text[], last_used_at, created_at, revoked_at (soft-delete), **expires_at** (OAuth: 30 dni, ręczne: NULL), oauth_client_id. Plaintext widoczny tylko raz przy generowaniu.
- `module_owners` - module (text, CHECK: kalendarz/teren/interpelacje/budzet/newsletter), user_id (FK profiles, CASCADE), position (1/2), PK (module, user_id), UNIQUE (module, position). SELECT: aktywny user + aal2; zapis tylko RPC `set_module_owners`

**Storage buckety:**
- `avatars` (public, 2 MB, JPG/PNG/WebP) — zdjęcia profilowe pracowników
- `site-assets` (public URL, 5 MB, JPG/PNG/WebP) — zdjęcia strony publicznej (`homepage/{timestamp}.{ext}`); SELECT/INSERT/UPDATE/DELETE tylko Posel/administrator + aal2, bez anonimowego listowania

**`app_settings` - konfiguracja instancji posła (ADR 026):**
- `site_identity` - mp_name, mp_name_genitive, mp_title, mp_gender (m/f - formy Poseł/Posłanka: `src/lib/mpForms.ts`, `api/_lib/siteIdentity.ts`), district_label, website_url, photo_url
- `budget_settings` - `monthly_limit_pln` (CHECK 1..1 000 000; SELECT aktywny + aal2)
- `district` - okręg instancji: number, highlighted_powiat_id, highlighted_gmina_id, highlight_label; publicznie przez RPC `get_public_district()`; mapy czytają `/geo/okreg-<number>-*.geojson`
- `homepage` - seo, promo, external_links, hero, sections (kolejność/widoczność offices/calendar/submit), offices, calendar, submit (steps), footer
- Zapis: UPDATE przez Posła/administratora + aal2 (polityka `app_settings_update_posel`), audyt `setting.update` (old_value/new_value). Odczyt publiczny: RPC `get_public_site_content()`

**Funkcje pomocnicze (SECURITY DEFINER):**
- `current_role()` - rola aktualnego usera
- `is_posel()` / `is_writer()` / `is_authenticated_active()` - predicaty do RLS
- `log_audit(action, entity_type, entity_id, metadata)` - wstawia wpis do audit_log; tylko triggery/RPC SECURITY DEFINER i service_role (nie authenticated)
- `log_client_event(action, ...)` - audyt z frontendu, allow-lista `mfa.enroll` / `mfa.verify_failed` / `mfa.unenroll`
- `service_log_audit(user_id, action, ...)` - service_role only (Edge Functions, Vercel OAuth), jawny aktor
- `get_public_office_staff(office_id)` - publiczna lista pracowników biura (anon dostep), zwraca tylko id/full_name/role/phone/avatar_url
- `get_public_site_content()` - publiczna treść strony (anon dostep), zwraca `{identity, homepage}` tylko z kluczy `app_settings` `site_identity` / `homepage` (brakujący klucz = `{}`)
- `mark_my_password_set()` - flaga `password_set=true` po pierwszym `auth.updateUser({password})`
- `set_my_privacy_pin(p_pin, p_current_pin)` / `verify_my_privacy_pin(p_pin)` / `clear_my_privacy_pin(p_current_pin)` - PIN trybu prywatnego (bcrypt w `profile_secrets`, 4-8 cyfr). Zmiana i wyłączenie wymagają obecnego PIN-u; 5 błędów → blokada 15 min (`privacy_pin_locked`); audit `privacy_pin.*`
- `get_user_admin_details(user_id)` - Posel + aal2 — szczegoly konta auth (last_sign_in_at, email_confirmed_at, sessions_count, mfa_factors_total/verified)
- `set_secret_setting(key, value)` / `get_secret_settings_status()` - Posel + aal2; klucze API `anthropic_api_key` / `getresponse_api_key` (bezpośredni dostęp klienta zablokowany polityką `app_settings_no_secret_keys`)
- `admin_revoke_user_sessions(user_id)` / `claim_public_submission_slot(...)` / `oauth_consume_code(...)` - service_role only
- `current_contacts_scope()` / `current_cases_scope()` / `current_events_scope()` / `current_interpellations_scope()` — zwracaja `data_scope` (own|all) z profilu callera; uzywane w SELECT policy danego modulu z bypassem dla Posla
- `create_mcp_token(name)` / `revoke_mcp_token(id)` - zarzadzanie tokenami MCP (Posel + aal2; plaintext zwracany jednorazowo, sha256 w DB)
- `mcp_consume_token(hash)` / `mcp_log_audit(user_id, action, ...)` - service_role only (wywolywane z Vercel `/api/mcp`); auto `metadata.via_mcp=true`. `mcp_consume_token` odrzuca tokeny wygasłe i tokeny unieważnionej OAuth App; `revoke_oauth_client` unieważnia tokeny aplikacji
- `set_module_owners(module, user_ids[])` - Posel + aal2; 1-2 różne aktywne konta, podmienia opiekunów modułu, audit `module_owners.update` (from/to)
- `get_module_pulse()` - aktywny user + aal2; wiersz per obszar: level (ok/warning/critical), recent_count, baseline_avg, reasons, owner_activity (liczby tylko Posel). Pomocnicze `module_pulse_decline`, `module_owner_activity` (bez grantów dla klienta)
- `get_person_pulse(user_id)` - Posel + aal2; trend osoby per miara (dni z logowaniem/MCP, akcje z `audit_log`, dodane wydarzenia, załatwione sprawy, wgrane interpelacje, wpisane wydatki): ten tydzień / poprzedni i ten miesiąc / poprzedni do tego samego momentu (Europe/Warsaw) + 8 tygodni

**RLS:** RLS na wszystkich tabelach. Poseł = pełne CRUD, Pracownik = read+write, Asystent = read.

## API Summary

**Edge Functions (Faza 1):**
- `admin-create-user` - tworzy konto + profil (z office_id), wysyła zaproszenie email. Tylko Poseł. Wymaga office_id dla rol != poseł.
- `admin-delete-user` - trwale usuwa konto (auth.users CASCADE → profiles). Tylko Poseł. Blokada self-delete. FK w innych tabelach SET NULL (historia zachowana).
- `admin-send-auth-link` - wysyla mail z linkiem do usera. Dynamicznie: `password_set=false` → invite (`inviteUserByEmail`, dla potwierdzonego konta magic link `signInWithOtp`); `password_set=true` → recovery (`resetPasswordForEmail`). Cooldown 5 min/user (sprawdzany w audit_log). Tylko Poseł + aal2, blokada self-link.
- `admin-revoke-user-sessions` - kill switch: RPC `admin_revoke_user_sessions` (usunięcie wszystkich sesji + refresh tokenow) + delete wszystkich MFA factor-ow. Audit `user.sessions_revoked`. Tylko Poseł + aal2, blokada self-revoke.
- `admin-reset-user-mfa` - usuwa wszystkie MFA factory usera (kazdy factor z auth.mfa_factors). Tylko Poseł + aal2, blokada self-reset.
- Wszystkie Edge Functions admina oraz `ai-proxy` / `getresponse-proxy` wymagają sesji aal2 (`_shared/auth.ts` → `isCallerAal2`) i audytują przez `service_log_audit`. `public-submit-case`: Turnstile (`TURNSTILE_SECRET`, `TURNSTILE_KEY`) + `claim_public_submission_slot` + walidacja pól.

**Vercel Serverless Functions:**
- `/api/mcp` (POST) - MCP server (JSON-RPC 2.0 over HTTP). Bearer token `epm_xxx` (ręczny albo z OAuth). Metody: `initialize` / `tools/list` / `tools/call` / `ping`; batch max 10. Audit kazdego wywolania z `via_mcp=true`. ENV: `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY`. Pliki: `api/mcp.ts`, `api/_lib/{auth,supabase,audit,jsonrpc}.ts`, `api/_lib/tools/*.ts`. Narzędzia: [features/mcp-integration.md](features/mcp-integration.md).
- `/api/oauth/{authorize,code,token}` + `/.well-known/oauth-authorization-server` - OAuth 2.0 (Authorization Code + PKCE S256) dla claude.ai. Ścisły walidator `redirect_uri` (`api/_lib/oauth.ts`), zgoda przez `POST /api/oauth/code` (akcje `describe` / `approve` / `deny`, wymaga aal2 - `api/_lib/jwt.ts`), kod zużywany atomowo (`oauth_consume_code`), token ważny 30 dni.
- `/api/integracje` - funkcja wielooperacyjna: `ics_sync` (Poseł + aal2; dawniej `/api/sync-ics`); `/api/cron/sync-ics` (`CRON_SECRET`, tylko aktywne źródła) - pobieranie przez `api/_lib/safe-fetch.ts` (ochrona SSRF, limit 5 MB). Wszystkie crony (`sync-ics`, `poliai-purge`, `notifications`) obsługuje jedna funkcja `api/cron/[job].ts` (limit 12 funkcji Vercel Hobby).
